# Plan Index

Status: active
Audience: humans and coding agents
Owner: repository maintainers

## Purpose

This file routes readers to active and future implementation plans.

Plans describe intended work. They are not evidence that work is already complete.
This file also does not decide which plan track an agent should follow without checking the task domain.

- `docs/21_PILOT_KNOWLEDGE_SYSTEM_PLAN.md`

## Reading Order

- For overall product implementation phases, start with `docs/12_IMPLEMENTATION_ROADMAP.md`.
- For repository knowledge-system rollout, read `docs/21_PILOT_KNOWLEDGE_SYSTEM_PLAN.md`.
- For documentation migration mechanics, read `docs/governance/DOCS_REFACTOR_PLAN.md`.

## Track Interpretation Rules

- Treat `docs/12_IMPLEMENTATION_ROADMAP.md` as the canonical source for product-delivery phases.
- Treat `docs/21_PILOT_KNOWLEDGE_SYSTEM_PLAN.md` and `docs/governance/DOCS_REFACTOR_PLAN.md` as support-track plans for documentation and repository structure.
- Do not switch from the product roadmap to a support-track plan unless the task is explicitly about documentation, governance, or knowledge-system rollout.
- If multiple plans are active, pick the plan that matches the task domain and state that choice explicitly in your work summary.
